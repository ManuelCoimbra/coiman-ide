# Speed and control win developers' loyalty

Developers use VS Code more than any other editor, but they do not love it the most. In the 2026 Stack Overflow survey VS Code had **70.9% usage but only 55.7% "admired"**. The most admired tools were fast, keyboard-centric editors with a strong identity: **Neovim 69.9%, Zed 57.3%, Rider 56.9%**. AI-first VS Code forks scored poorly: **Cursor 33.0%, Windsurf 22.7%** ([SO 2026](https://survey.stackoverflow.co/2026/technology/data)). Across every editor family the same pattern holds. Developers like speed, zero-config defaults that work, deep integrated tooling (LSP, debugger, Git) and real control. They dislike bloat, AI and telemetry they cannot switch off, network activity they did not consent to, opaque usage-based pricing, forced UI changes, lock-in, and extensions that run unsandboxed. The most popular extensions and plugins are a map of what editors fail to ship: inline diagnostics, a real Git UI, formatters, runners, icons, Vim modes and fuzzy pickers. For "Rust Code" the evidence points to a clear strategy. First, replace egui `TextEdit` with a custom rope-backed, virtualized editor widget. Then add tree-sitter, a rust-analyzer-first LSP client, a real PTY terminal, Git, Cargo integration, and later a DAP debugger. Make privacy, consent and an AI-optional design part of the architecture from the start. Do not try to clone VS Code's extension API, and do not become another AI fork. JetBrains Fleet, Atom and Lapce show that "lighter and more modern" alone does not pull users away from VS Code. A narrow, polished niche does, and fast native Rust tooling is that niche.

## Usage leaders are not the editors developers love

VS Code's dominance is real but has peaked. It led usage at **73.6% (2024), 75.9% (2025) and 70.9% (2026)** ([SO 2024](https://survey.stackoverflow.co/2024/technology); [SO 2025](https://survey.stackoverflow.co/2025/technology); [SO 2026](https://survey.stackoverflow.co/2026/technology/data)). The 2026 drop needs caution, because only 13,193 people answered the 2026 IDE question, against roughly 49,000 respondents overall in 2025. Notepad++ (27.8%), Visual Studio (27.6%), Vim (27.2%) and IntelliJ IDEA (24.3%) form a second tier of tools that people keep alongside their main editor. The fastest riser is **Zed, from 7.3% in 2025 to 11.4% in 2026**. Cursor went the other way, **from 17.9% to 14.9%** ([SO 2026](https://survey.stackoverflow.co/2026/technology/data); [SO 2025](https://survey.stackoverflow.co/2025/technology)). Neovim's admiration is stable: it was most admired at about 83% in 2024 ([Visual Studio Magazine](https://visualstudiomagazine.com/articles/2024/07/26/so-dev-survey.aspx)), and still leads in 2026.

The gap between used and admired matters more than the usage figure. Tools that score high on admiration share three traits: low latency, keyboard efficiency, and a clear point of view. Tools people try and then leave are, overwhelmingly, AI-first VS Code forks. This matches AI sentiment generally. Use is near-universal: **84% use or plan to use AI (2025)** and **only 17.2% use no AI tools (2026)**. Trust is falling: **only 33% trust AI accuracy, 46% distrust it**, and **66% cite "almost right" output** as their top frustration ([SO 2025 AI](https://survey.stackoverflow.co/2025/ai); [IT Brief UK](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)). In 2026, **AI features were cited by only 2% as a reason to recommend a technology**. Nearly half trust only output they can easily verify, and **78.7% call source attribution important** ([IT Brief UK](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)). So AI is a table-stakes capability, but it does not create loyalty. What earns loyalty is an excellent core editor with AI that can be checked and removed.

Rust developers, the target audience for Rust Code, are already moving. The 2024 State of Rust survey found VS Code "still remains the most popular option, its share has dropped by 5pp", while Zed "gained considerable traction" ([Rust blog 2024](https://blog.rust-lang.org/2025/02/13/2024-State-Of-Rust-Survey-results/)). The 2025 survey (7,156 responses) says Zed "did a remarkable jump upward", Helix is a "good second", and agentic editors are "eroding the userbase of VSCode and IntelliJ" ([Rust blog 2025](https://blog.rust-lang.org/2026/03/02/2025-State-Of-Rust-Survey-results)). Rust users' top problems are slow compiles and disk usage. "Subpar support for debugging Rust" was second in 2024 and fourth in 2025. Users also name rust-analyzer and rustfmt as "slow or resource intensive", and ask for "a better IDE story" ([Rust blog 2024](https://blog.rust-lang.org/2025/02/13/2024-State-Of-Rust-Survey-results/); [Rust blog 2025](https://blog.rust-lang.org/2026/03/02/2025-State-Of-Rust-Survey-results)). Exact Rust-survey editor shares were only available as chart images and could not be extracted, so the direction is clear but the magnitudes are not.

## What developers refuse: forced AI, silent telemetry, lock-in and surprise bills

The strongest negative sentiment in 2025–2026 is not about missing features. It is about tools acting without consent. On 16 April 2026, VS Code began **adding "Co-authored-by: Copilot" to commits by default, even with AI disabled**. The VS Code lead apologized on Hacker News for "a mistake made without sufficient upfront validation", and the default was reverted in 1.119 ([Windows Central](https://windowscentral.com/software-apps/this-could-cost-people-their-jobs-vs-code-added-copilot-as-co-author-without-permission-or-notice); [WebProNews](https://www.webpronews.com/vs-codes-sneaky-copilot-co-authorship-how-microsoft-rewrote-git-histories-and-lost-developer-trust/)). Earlier, a Copilot icon came back after the extension had been uninstalled ([The Register](https://www.theregister.com/2025/09/05/github_copilot_complaints/)). The VS Code issue "Require user consent before sending any telemetry" has **1,005 upvotes and is still open** ([GitHub #176269](https://github.com/microsoft/vscode/issues/176269)). Copilot Chat has 79.0M installs but a **2.78 rating**, and Microsoft's proprietary language extensions rate similarly badly: Pylance 2.95, C# Dev Kit 2.32, Python Environments 1.3 (marketplace snapshot, [notes source](https://marketplace.visualstudio.com/)). Zed met the same pressure differently. In July 2025 it added a global `"disable_ai": true` setting after users raised training-data, legal, environmental and predictability objections ([Zed blog](https://zed.dev/blog/disable-ai-features)). Its top-reacted issues still include **"Zed downloads NodeJS binary and npm packages from Internet without user's consent"** and an offline-mode meta-issue ([Zed issues](https://github.com/zed-industries/zed/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc)).

Telemetry scandals show what happens when opt-out is ignored. ByteDance's Trae, with telemetry disabled, still made **about 500 calls in about 7 minutes, sending up to 26 MB**, including persistent machine IDs and full file paths ([The Register](https://www.theregister.com/2025/07/28/bytedance_trae_telemetry/)). JetBrains lets RustRover's free non-commercial users **not opt out of anonymous usage statistics** ([InfoQ](https://www.infoq.com/news/2024/06/rust-jetbrains-ide)). VSCodium, which exists mainly to strip Microsoft telemetry and branding, holds a steady **4.8–6.2% usage** share, a measurable privacy-first niche ([SO 2024](https://survey.stackoverflow.co/2024/technology); [SO 2025](https://survey.stackoverflow.co/2025/technology/)).

Lock-in and pricing make up the second cluster. In April 2025 Microsoft's C/C++ extension (106M installs) began **blocking forks such as Cursor and VSCodium at runtime** ([The Register](https://www.theregister.com/2025/04/24/microsoft_vs_code_subtracts_cc_extension/)). Microsoft's marketplace terms also keep Remote-SSH, Dev Containers and Live Share away from forks ([ArchWiki](https://wiki.archlinux.org/title/Code)). Cursor's June 2025 switch from request-based to compute-based limits left users out of credit after "a handful of prompts" and ended in apologies and refunds ([TechCrunch](https://techcrunch.com/2025/07/07/cursor-apologizes-for-unclear-pricing-changes-that-upset-users/)). Cursor also stays months behind upstream; staff say a VS Code rebase "isn't in the near-term plans" ([Cursor forum](https://forum.cursor.com/t/outdated-vscode-version-vscode-version-1-105-1/156543/4)). JetBrains users complain that the value of an AI credit is never explained, and one reported the same file being sent about 30 times in a single prompt ([JetBrains forum](https://intellij-support.jetbrains.com/hc/en-us/community/posts/29142783285266?page=2)). Replit's effort-based billing pushed some bills **from $20 to $350+ in a day** ([The Register](https://www.theregister.com/2025/09/18/replit_agent3_pricing/)).

The third cluster is supply-chain safety and feature creep. VS Code extensions run with full user privileges. The GlassWorm campaign hit Open VSX repeatedly from October 2025 to April 2026. It stole credentials and used `extensionPack` dependencies to pull in hidden loaders on update ([InfoWorld](https://www.infoworld.com/article/4145589/open-vsx-extensions-hijacked-glassworm-malware-spreads-via-dependency-abuse-2.html); [The Hacker News](https://thehackernews.com/2026/04/researchers-uncover-73-fake-vs-code.html)). Of about 45,000 Microsoft marketplace publishers, only about 1,800 are verified ([Koi Security](https://www.koi.security/blog/2-6-exposing-malicious-extensions-shocking-statistics-from-the-vs-code-marketplace)). Notepad++'s updater was **hijacked for selected users from about June to December 2025** because of weak update integrity checks ([The Register](https://www.theregister.com/2026/02/02/notepad_plusplus_intrusion/)). Windows Notepad added Markdown, AI "writing tools" tied to a Microsoft account, and a "What's New" startup screen. The Register framed that as listing "all the ways Microsoft has enshittified it" ([The Register](https://www.theregister.com/2026/01/22/microsoft_notepad_update/)). The new Markdown link handling then produced **CVE-2026-20841, a CVSS 8.8 command-injection bug** ([The Register](https://www.theregister.com/2026/02/11/notepad_rce_flaw/)). The lesson: users accept quality-of-life features that keep a tool's identity, such as tabs and session restore. They reject features that change its character, and every new renderer or link handler is attack surface.

Forced change is the final irritant. JetBrains made the New UI the default in 2024.2 and moved the Classic UI to a plugin. Developers complained that it was "a VS Code lookalike". JetBrains later admitted its onboarding "weren't always enough" ([DevClass](https://devclass.com/2024/08/06/jetbrains-updates-ides-with-new-ui-by-default-now-a-vs-code-lookalike-some-devs-think-so/); [JetBrains blog](https://blog.jetbrains.com/idea/2024/10/bridging-the-gap-between-the-classic-and-new-uis/)). Neovim users describe config churn, such as the nvim-lspconfig framework being deprecated in September 2025, and setup as a "nightmarish experience" ([DEV](https://dev.to/m15a/housekeeping-my-neovim-configuration-4kim); [LWN](https://lwn.net/Articles/1015499)).

The VS Code marketplace is the clearest evidence of what users want and core editors do not ship. Its top installs are Microsoft language stacks (Python 242.5M, Pylance 209.2M, Jupyter 110.7M, C/C++ 106.1M) and Remote tooling (WSL 41.1M, Dev Containers 42.4M, Remote-SSH 38.2M). Below them sits a long tail of gap-fillers, and their ratings show how badly users want each gap closed (live marketplace snapshot, 24 Oct 2026, from the [VS Code Marketplace](https://marketplace.visualstudio.com/)). Install counts include auto-installed companions and CI installs, so they overstate deliberate choice. Ratings are the better satisfaction signal.

The open-issue tracker tells the same story from the other side. VS Code's most upvoted open request, **"Change font size/font of the workbench", has 3,790 upvotes and has been open since 2015**. Close behind are mouse-button bindings (1,932), project-wide diagnostics (1,509), a built-in Vim mode (1,370), settings inheritance (1,368), macro recording (1,228), per-platform settings (1,150), local uncommitted workspace settings (1,043), telemetry consent (1,005), grouped tabs (854), enable/disable extensions from a config file (840), a detachable terminal (810), variables in settings (742), tree-sitter highlighting (739), vertical tabs (659), ignore-whitespace diffs (635) and printing (626) ([GitHub open issues](https://github.com/microsoft/vscode/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc)). Most of these concern configuration and layout, not intelligence. A new editor can design them in cheaply on day one, while VS Code has spent ten years unable to change its settings model. Zed's top requests are parity items: test runner integration, Find All References as a panel, multi-window, settings sync, 3-way merge, configurable mouse bindings, localization, and offline/consent controls ([Zed issues](https://github.com/zed-industries/zed/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc)).

Other ecosystems fill the same holes. Neovim's most-used plugins do the same jobs: fuzzy finders (telescope, fzf-lua, snacks), completion (nvim-cmp moving to blink.cmp, chosen for speed), and plugin managers. Neovim core is now absorbing the plugin-manager and LSP-config roles, through `vim.lsp.config` in 0.11 and `vim.pack` in 0.12 ([heise](https://www.heise.de/en/news/Neovim-0-12-with-native-plugin-manager-11241587.html?view=print); [Dotfyle](https://www.dotfyle.com/plugins/nvim-telescope/telescope.nvim)). Notepad++ users install XML Tools and JsonTools for format/validate, and NppExec to pipe the buffer through a compiler, plus scripting plugins ([Notepad++ Community](https://community.notepad-plus-plus.org/post/104851)). Emacs's killer app, Magit, shows how much a keyboard-driven Git UI is worth. Hunk-level staging "is as trivial as staging a whole file", and users say it taught them Git ([Magit](https://magit.vc/about/)). People pay for JetBrains because its Git tool window, index-backed Find Usages and Search Everywhere, debugger with conditional breakpoints and log points, shareable run configurations, database tools and local history work without assembling extensions ([mokkapps](https://mokkapps.de/blog/why-i-switched-back-from-vscode-to-intellij-idea); [JetBrains local history](https://blog.jetbrains.com/ko/2020/03/26/local-history-intellij-save-your-code-ko)).

Two lightweight-editor expectations are underrated. The first is **hot exit**, meaning crash-safe restore of unsaved tabs. Notepad++ users keep unsaved tabs for years, and Windows Notepad made restore the default in 2023. Lost tabs after an update or crash cause the angriest threads ([Notepad++ Community](https://community.notepad-plus-plus.org/post/89419); [Thurrott](https://www.thurrott.com/windows/windows-11/288011/notepad-and-snipping-tool-are-getting-new-features)). The second is **huge files**. In one 2019 benchmark BBEdit opened a 1.5 GB CSV about 4x faster than VS Code ([Birchtree](https://birchtree.me/blog/how-long-to-the-major-macos-text-editors-take-to-open-huge-files/)). VS Code can crash on a too-large file and then reopen it on every launch through its backup directory ([bobbyhadz](https://bobbyhadz.com/blog/vscode-taking-too-much-memory)). No recent controlled large-file benchmark exists, so "opens a multi-GB log without freezing" is a differentiator Rust Code can claim and prove.

## The Rust stack dictates a custom editor core on top of egui

Rust Code's biggest current liability is its foundation, egui `TextEdit`. egui's own README warns that "having a very large UI in a scroll area (with very long scrollback) can be slow" and that immediate mode "makes layout more difficult" ([egui README](https://github.com/emilk/egui/blob/main/README.md)). In egui issue #3086, with about 15M characters, **inserting one character took more than 1 s**, because `TextEdit` lays out and tessellates all text, not only the visible part. The April 2025 fix caches layout per paragraph but does not cull to the viewport ([egui #3086](https://github.com/emilk/egui/issues/3086)). `TextEdit` uses a single `CCursorRange`, so it has no multi-cursor ([egui PR #5785](https://github.com/emilk/egui/pull/5785)). It also has a 0.37 regression in which clicking an outside button collapses the selection before the button's code runs ([egui #8763](https://github.com/emilk/egui/issues/8763)). Neither Zed (GPUI) nor Lapce (Floem) used egui for its editor surface. Both built their own rendering for it ([GPUI README](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md); [Lapce](https://lap.dev/lapce/)). The correct split is to keep egui for the app chrome (panels, tabs, palette, settings, dialogs) and own a custom-painted editor viewport. That viewport needs a rope buffer, visible-lines-only layout, per-line galley caching keyed by content hash, a monospace column grid, a multi-cursor selection model and transaction-based undo. The hidden cost is real. A custom widget must re-implement IME composition, clipboard, keyboard navigation and AccessKit text nodes, all of which `TextEdit` currently provides ([AccessKit PR #145](https://github.com/AccessKit/accesskit/pull/145)).

For the buffer, **crop** indexes by UTF-8 bytes, which matches tree-sitter and LSP's UTF-8 position encoding. On its author's own edit-trace benchmark it is about 3.5x faster than Ropey (12.39 ms vs 44.14 ms). **Ropey** is the conservative choice, battle-tested by Helix. Both give O(1) clones for background snapshots ([crop docs](https://docs.rs/crate/crop/latest)). Zed's SumTree shows the destination: Arc-cheap snapshots handed to background tree-sitter parsing, and multi-dimensional summaries (bytes, lines, UTF-16) for O(log N) LSP position conversion ([Zed blog](https://zed.dev/blog/zed-decoded-rope-sumtree)). Put the rope behind a small trait and add a UTF-16 conversion helper, since neither crate tracks UTF-16 natively.

For highlighting, syntect's author calls it "mostly complete", not under heavy development. It took about 600 ms on a 9,200-line file on a 2012 laptop, against about 98 ms in Sublime ([syntect](https://github.com/trishume/syntect)). The xi-editor retrospective calls regex highlighting "slow and imprecise" and recommends tree-sitter ([xi retrospective](https://raphlinus.github.io/xi/2020/06/27/xi-retrospective.html)). tree-sitter 0.27.1 offers incremental reparse through `tree.edit()` and optional WASM grammar loading, the model Zed uses for language extensions ([docs.rs tree-sitter](https://docs.rs/crate/tree-sitter/latest); [Zed blog](https://zed.dev/blog/zed-decoded-extensions)). tree-sitter also unlocks folding, outline, syntax-node selection and textobjects, and VS Code users have requested it for eight years (#50140, 739 upvotes). Keep syntect as the fallback for languages without a grammar, with cached line-start parse states.

For intelligence, there is **no turnkey Rust LSP client**. Use `lsp-types` with a custom JSON-RPC-over-stdio transport, or async-lsp, which supports client roles. The DAP crates are weak (`dap` is server-oriented and early, `debug_types` is stale), so plan to hand-roll a DAP client on the same Content-Length framing, as Helix did ([async-lsp](https://github.com/oxalica/async-lsp); [docs.rs dap](https://docs.rs/crate/dap/latest)). Language servers must never block the egui frame. Run one task per server, send results over channels, and call `request_repaint()`. Expect a real debugger to be a large effort. Zed's took **about 8 months, about 1,000 commits and more than 25k lines** ([Zed blog](https://zed.dev/blog/debugger)).

For the terminal, **alacritty_terminal 0.26** supplies the VTE parser and grid. **portable-pty 0.9** (from wezterm) or alacritty's own tty layer spawns the shell, through ConPTY on Windows 10 1809+ ([docs.rs alacritty_terminal](https://docs.rs/crate/alacritty_terminal/latest); [docs.rs portable-pty](https://docs.rs/crate/portable-pty/latest)). Both are thinly documented, and painting the grid, selection, scrollback and key mapping in egui is custom work. A PTY terminal matters more than it looks. With **Claude Code at 9.7% usage and 28.6M extension installs**, many developers want their editor to host external CLI agents ([SO 2025](https://survey.stackoverflow.co/2025/technology/)). A real terminal is the cheapest, vendor-neutral AI integration Rust Code can ship.

For Git, **gix** is pure Rust and fast for read paths such as status, diff and log, but the `gix` crate is still in an "initial development / usable" tier, and blame and rebase are early or placeholders ([gitoxide README](https://github.com/GitoxideLabs/gitoxide/blob/main/README.md)). Use gix for reads and shell out to the `git` CLI for writes. That inherits the user's credentials, SSH agent and hooks.

For plugins, Zed's model of **Rust compiled to WASM components, defined in WIT and run in Wasmtime** gives sandboxing and crash isolation ([Zed blog](https://zed.dev/blog/zed-decoded-extensions)). Its deliberately narrow API, with no panels, webviews or arbitrary HTTP, is now a top complaint (#21208). Implementing the VS Code extension API would mean embedding Node and a browser engine. Even Theia, built for exactly that, admitted it lacked 100% API coverage, and Microsoft's marketplace is off-limits to non-Microsoft products ([Theia FAQ](https://theia-ide.org/docs/faq/); [EclipseSource](https://eclipsesource.com/blogs/2021/03/24/vs-code-extensions-vs-theia-extensions)). The cheap path to ecosystem reuse is the pure-data assets: VS Code JSON themes, TextMate grammars (through syntect), snippets, and above all language servers and debug adapters. Treat languages as "servers, not extensions".

Three more constraints round out the stack. For fuzzy matching, **nucleo** (from Helix) is about 6x faster than skim, and its matcher core is "finished and ready for wide use" ([nucleo](https://github.com/helix-editor/nucleo)). For text quality, Zed's grayscale glyph antialiasing produces blurrier text than VS Code on low-DPI Windows screens. egui's default rasterization is also grayscale, so expect the same complaint ([Zed commit](https://git.secluded.site/zed/commit/c0259a448d6052222e8492538594e3d0e88733ae.patch)). For accessibility, egui implements native AccessKit on Windows and macOS only. Microsoft's CodeTalk research notes that even VS Code fails to announce live errors and refactoring hints to screen-reader users ([egui README](https://github.com/emilk/egui/blob/main/README.md); [Microsoft Research](https://www.microsoft.com/en-us/research/blog/codetalk-rethinking-ide-accessibility)). The xi retrospective adds the process-level warnings. Splitting frontend and core into separate processes and pervasive async "made everything more complicated", and a CRDT does not suit core text editing. Use a single process with threads and channels, and keep only language servers and plugins outside it ([xi retrospective](https://raphlinus.github.io/xi/2020/06/27/xi-retrospective.html)).

## Roadmap: rebuild the core first, then earn the IDE label

The roadmap follows one principle drawn from Atom, Lapce and Fleet: **polish the core loop of typing, scrolling, search and LSP before adding breadth, and pick a niche.** The niche is the fastest, most respectful editor for Rust developers. It should start as quickly as Notepad++, ship zero-config defaults like Helix, offer JetBrains-grade Git, Cargo and debugging, and never act without consent. The phases below are ordered by dependency and evidence weight, not by calendar.

### Key architecture decisions

| Decision | Recommendation | Evidence driving it |
|---|---|---|
| Editor widget | Custom egui widget (`allocate_rect` + `Painter`): visible-lines-only layout, per-line galley cache, monospace grid, multi-cursor, own undo. Keep `TextEdit` only for small inputs | `TextEdit` relays out all text ([#3086](https://github.com/emilk/egui/issues/3086)); single cursor ([#5785](https://github.com/emilk/egui/pull/5785)); Zed and Lapce own their surfaces |
| Buffer | Rope behind a trait: crop (UTF-8 bytes, faster) or Ropey (proven in Helix). Arc snapshots to workers. UTF-16 helper for LSP | [crop](https://docs.rs/crate/crop/latest); [Zed SumTree](https://zed.dev/blog/zed-decoded-rope-sumtree); xi "rope is a success" |
| Highlighting | tree-sitter (incremental, background thread, WASM-loadable grammars); syntect fallback with cached parse states | [tree-sitter 0.27.1](https://docs.rs/crate/tree-sitter/latest); [syntect speed](https://github.com/trishume/syntect); VS Code #50140 |
| Language intelligence | Built-in LSP client (lsp-types or async-lsp, custom stdio transport), rust-analyzer first. Never block the frame | Sublime lost users by leaving LSP to a volunteer plugin ([HN](https://hn.svelte.dev/item/44961172)); Kate config friction |
| Debugger | Hand-rolled DAP client reusing the LSP framing; CodeLLDB as first adapter | Weak DAP crates ([dap](https://docs.rs/crate/dap/latest)); Rust debugging pain ([Rust blog](https://blog.rust-lang.org/2025/02/13/2024-State-Of-Rust-Survey-results/)) |
| Terminal | alacritty_terminal grid + portable-pty/ConPTY; custom egui grid painter | [alacritty_terminal](https://docs.rs/crate/alacritty_terminal/latest); hosts CLI agents |
| Git | gix for reads (status, diff, blame, log); `git` CLI for writes; Magit-style hunk verbs | [gitoxide status](https://github.com/GitoxideLabs/gitoxide/blob/main/README.md); [Magit](https://magit.vc/about/) |
| Process model | Single process, threads + channels; servers and plugins out-of-process or sandboxed; no CRDT | [xi retrospective](https://raphlinus.github.io/xi/2020/06/27/xi-retrospective.html) |
| Settings | Layered TOML: default, user, platform, profile, workspace, local-uncommitted; inheritance, variables, declarative plugin enable list; separate UI and editor font scale; keybindings file including mouse buttons | VS Code #519, #15909, #5595, #40233, #2809, #40239, #3130 |
| Plugins | Phase 1: data assets (VS Code themes, TextMate grammars, snippets) + "servers not extensions". Phase 2: WASM components (WIT/Wasmtime) with declared capabilities and declarative UI contribution points, signed publishers, lockfile, no silent dependency installs | [Zed extensions](https://zed.dev/blog/zed-decoded-extensions); GlassWorm ([InfoWorld](https://www.infoworld.com/article/4145589/open-vsx-extensions-hijacked-glassworm-malware-spreads-via-dependency-abuse-2.html)); Helix's #1 complaint |
| AI | Not in core. A PTY terminal for CLI agents first; later an optional, separately compiled module: bring-your-own-key, local/OpenAI-compatible endpoints, multiple providers, per-hunk diff review, provenance labels, a global `ai.enabled=false` that removes all UI | Trust and attribution data ([IT Brief](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)); [Zed disable_ai](https://zed.dev/blog/disable-ai-features); co-author incident |
| Telemetry and network | No telemetry by default. Opt-in only, with a viewable payload. No network call (server downloads, update checks) without explicit consent; an offline mode | VS Code #176269; Zed #12589/#24878; [Trae](https://www.theregister.com/2025/07/28/bytedance_trae_telemetry/) |
| Accessibility | Custom widget emits AccessKit text nodes (caret, selection, lines); announce diagnostics; full keyboard reachability; high-contrast themes | [egui AccessKit scope](https://github.com/emilk/egui/blob/main/README.md); [CodeTalk](https://www.microsoft.com/en-us/research/blog/codetalk-rethinking-ide-accessibility) |
| Updates | Signed releases, signature-pinned verification, no startup nag screens | [Notepad++ hijack](https://www.theregister.com/2026/02/02/notepad_plusplus_intrusion/); [Notepad nag backlash](https://www.theregister.com/2026/01/22/microsoft_notepad_update/) |

### Performance targets

Latency research finds that **even 20 ms of added latency is noticeable**. It recommends **1–5 ms of editor paint time**, and found Electron-based Atom at 49.4 ms average typing latency against GVim at 0.9 ms and Sublime at 8.2 ms ([Pavel Fatin](https://pavelfatin.com/typing-with-pleasure/)). At 120 Hz a frame has 8.33 ms ([Zed blog](https://zed.dev/blog/videogame)). Sublime and Notepad++ users prize cold starts "under a second" ([pivotlog](https://pivotlog.net/switched-away-from-vs-code/)). These suggest the following budgets. They are targets derived from that evidence, not measured competitor baselines; no modern independent benchmark of VS Code, Zed or Cursor latency exists.

| Metric | Target | Rationale |
|---|---|---|
| Keystroke-to-paint (editor work per frame) | p99 ≤ 4 ms on a 10k-line Rust file; independent of file size | 1–5 ms guidance; 120 Hz budget |
| Cold start to editable window | ≤ 300 ms without restore; ≤ 600 ms restoring 20 tabs | Sublime/Notepad++ expectations |
| Idle RAM (empty window / 1 Rust workspace, excluding rust-analyzer) | ≤ 80 MB / ≤ 250 MB | VS Code memory is the top switch reason |
| Quick open over 100k files | first results ≤ 30 ms after keystroke | nucleo 2–10 ms per pattern ([nucleo](https://github.com/helix-editor/nucleo)) |
| Open 2 GB log | first screen ≤ 1 s, scrolling at frame rate; highlighting/LSP auto-off above a threshold | BBEdit/EmEditor bar; VS Code crash loop |
| UI never blocks | 0 frames > 50 ms from LSP, Git, search or indexing | JetBrains indexing and Emacs stalls |

Publish these numbers from a CI benchmark harness. A latency claim users can reproduce is a marketing asset, since no competitor publishes one.

### Now: rebuild the foundation (makes everything else possible)

| Priority | Item | Why now |
|---|---|---|
| 1 | Custom rope-backed editor widget: virtualized painting, per-line cache, multi-cursor (Ctrl+D, Alt+click, column select), transactional undo/redo, IME, clipboard, basic AccessKit. Port existing line actions (comment, move/copy/delete line, indent, bracket jump, wrap) onto it | `TextEdit` cannot scale, has no multi-cursor, and blocks every later feature |
| 2 | Hot exit: continuous, atomic, journaled persistence of unsaved buffers, on by default, with a recovery view; never auto-reopen a file that crashed the app | The deepest trust failure in Notepad++/VS Code threads |
| 3 | tree-sitter highlighting on a background thread (Rust, TOML, Markdown, JSON, YAML first); syntect fallback; bracket-pair colorization; indent guides | Speed, precision, and foundation for folding/outline |
| 4 | Layered TOML settings and keybinding files, separate UI and editor font scale, theme import from VS Code JSON | Ten-year-old VS Code requests that are cheap only if designed in now |
| 5 | Workspace engine: `ignore` walker + nucleo for quick open, ripgrep crates for find-in-files streamed to a results tab, `notify` for reload-on-change | Fast pickers are the most admired Neovim/Helix trait |
| 6 | Large-file mode, encoding and line-ending detection and conversion in the status bar | Measurable differentiator against VS Code |
| 7 | Benchmark harness and the privacy baseline: no telemetry, no network calls, signed builds | Avoid retrofitting trust later |

| Priority | Item | Why |

| Priority | Item | Why |
|---|---|---|

| 2 | WASM plugin API (WIT/Wasmtime) with capability permissions, declarative UI contribution points (panels, tree views, status items), signed registry, lockfile and update diffs | Helix's #1 complaint; Zed's UI-less limitation; GlassWorm |
| 3 | Optional AI module: BYOK, local models, multiple providers, inline next-edit suggestions, agent edits as per-hunk reviewable diffs with action logs, admin-enforceable disable | AI is table stakes but low-trust and low-loyalty |

| 5 | 3-way merge editor, commit graph, interactive rebase | VS Code #179053, Zed #34813, JetBrains praise |
| 6 | Workflow polish: macro recording, mouse-button bindings, grouped/vertical tabs, multi-window, named sessions with split layouts, printing, two-tab compare, JSON/XML format and validate | VS Code #4490, #3130, #100335, #108264; Kate and Notepad++ habits |

### Do not do these things

| Don't | Evidence |
|---|---|
| Fork or chase compatibility with the VS Code extension API | Cursor's rebase lag; Theia's incomplete coverage; Microsoft's marketplace terms and fork-blocking extensions |
| Ship AI on by default, re-enable it on update, or touch commits, files or Git metadata without explicit action | Copilot co-author incident; Copilot icon returning; Notepad AI backlash |
| Send telemetry, download servers or check for updates without opt-in consent | VS Code #176269 (1,005 upvotes); Zed #12589; Trae |
| Require an account, or show startup nag or "What's New" screens | Windows Notepad backlash; Sublime upgrade "dark patterns" |
| Meter AI with opaque credits or resell tokens with a hidden margin | Cursor refunds; JetBrains credit complaints; Replit bills |
| Block editing or navigation on indexing, LSP, Git or search | JetBrains reindexing; Emacs single-thread stalls |
| Run plugins unsandboxed or let them silently pull dependencies | GlassWorm `extensionPack` abuse; MaliciousCorgi |
| Leave core IDE features (LSP, Git, debugging) to volunteer plugins | Sublime's churn; Helix's missing-plugin ceiling cuts the other way, so ship both a strong core and an API |
| Rewrite or fork the UI toolkit mid-project, or split frontend and core into processes | Lapce's Druid-to-Floem rewrites; xi retrospective |
| Force layout or keymap changes on existing users | JetBrains New UI backlash |
| Add rich-content renderers (Markdown preview, links) without treating them as a security boundary | Notepad CVE-2026-20841 |
| Stay in perpetual preview or reposition repeatedly | Fleet's discontinuation |
| Build a CRDT or collaboration layer into the core buffer | xi retrospective: CRDT costly and a poor fit |

## Conclusion

The evidence shows a market split between what developers use and what they love, and that split is Rust Code's opening. VS Code's lead comes from accumulated ecosystem and Microsoft-maintained language and remote tooling. Its weakest scores come from things it does to users rather than for them. That makes respect for the user (consent, privacy, removable AI, stable UI, sandboxed plugins) as much a product feature as speed. A small team can deliver it more credibly than a platform owner whose roadmap is now dominated by agents. A Rust-written editor also has a structural advantage on exactly the axes Rust developers complain about: memory, responsiveness while rust-analyzer is busy, and debugging UX.

The sharper insight is about sequencing. Every failed or stalled challenger examined here (Atom, xi, Lapce, Fleet) tried to win on architecture or breadth before the core loop felt finished. Every admired one (Sublime, Helix, Zed, Neovim) won on a small set of things done exceptionally well and shipped as defaults. For Rust Code, that means the custom editor widget and hot exit are worth more today than any new panel. A real PTY terminal is the most cost-effective "AI feature" available. Published latency numbers and a written no-telemetry, no-surprise policy will do more for adoption than feature parity. The open uncertainties are exact Rust-survey editor shares, modern cross-editor latency benchmarks, and the current state of egui's AccessKit text support. Measure all three directly before finalizing the "Later" phase.
